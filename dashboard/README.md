# Convex dashboard on Laravel Cloud

Deploy the official self-hosted Convex dashboard as a separate Cloud application. It connects to your existing backend and lets you manage tables, functions, logs, and function environment variables.

This folder packages the dashboard setup from Lawn. It downloads the application layers from the official Convex container image, verifies their SHA-256 hashes, and runs its standalone Next.js server with Node. Docker is not required on Cloud.

## Deploy

Create another Laravel Cloud application from this repository:

| Setting | Value |
| --- | --- |
| Branch | `main` |
| Root directory | `dashboard` |
| Runtime | Node.js 22 |
| Build commands | `npm run build` |
| Deploy commands | Leave empty |
| Start command | `npm start` |
| Database and bucket | None; the backend owns these resources |

Set the backend's public HTTPS origin in the dashboard environment:

```dotenv
NEXT_PUBLIC_DEPLOYMENT_URL=https://YOUR-BACKEND.laravel.cloud
```

Use the backend URL without `/http` or a trailing slash. Cloud supplies `PORT`. The start script sets `HOSTNAME=::` so the server accepts Cloud's IPv6 traffic.

Here, `npm run build` invokes `node build.mjs`, and `npm start` invokes `HOSTNAME=:: node dist/app/dashboard-self-hosted/server.js`. These differ from the backend's Bash commands.

Deploy and open the dashboard's public URL. Enter the admin key generated by your backend. Do not set `NEXT_PUBLIC_ADMIN_KEY`, publish the key in this repository, or embed it in a link. The backend URL is public configuration; the admin key grants administrative access.

The browser connects directly to the backend. The dashboard does not proxy the backend or need database credentials. A MySQL-backed Convex deployment works with the same dashboard.

## Verify

1. Open the dashboard URL and confirm the backend URL is correct.
2. Sign in with that backend's admin key.
3. Confirm tables and functions appear and logs load.
4. Reload a nested page such as `/data` and check that it still loads.
5. Verify a realtime query updates after a mutation in a test deployment.

This folder is adapted from Lawn's dashboard work. Publishing it does not verify a Cloud deployment; run these checks on your environment before relying on it.

## Versions and build requirements

`build.mjs` pins the application-layer hashes for:

```text
ghcr.io/get-convex/convex-dashboard:27ef2346e0fea1f7e9fbfe7bfae895164c89dbec
```

That commit matches backend release `precompiled-2026-09-26-27ef234`. Linux ARM64 and x64 application layers are included. The build needs Node.js, `tar`, outbound HTTPS to GHCR, and enough temporary disk for the archives and extracted files. The downloaded `dist/` directory is ignored by Git.

To upgrade, choose a compatible upstream image, update both architectures' application-layer hashes in `build.mjs`, rebuild, and test login, data editing, logs, and nested navigation. There is no dashboard version environment override in this implementation.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Cloud reports an unhealthy application | Keep `HOSTNAME=::` in the start script and let Cloud supply `PORT`. |
| Missing `server.js` | Check build completion and use `dashboard` as the application root. |
| GHCR download or checksum failure | Check build network access and the pinned upstream image; do not bypass checksum verification. |
| Build runs out of disk | Increase the dashboard application's compute size to provide more temporary disk. |
| Login fails | Check the public backend URL and use an admin key generated for that backend's instance identity. |
| Dashboard opens but cannot load data | Check the browser's access to the backend and its WebSocket connection. |
